# Melearn UI / UX Spec

ส่วนรายงานธุรกิจ/การเงินที่เพิ่ม 1 ต.ค. 2026 ใช้ [BUSINESS_ANALYTICS_UI_SPEC.md](BUSINESS_ANALYTICS_UI_SPEC.md) ร่วมกับกติกาแบรนด์ไฟล์นี้ แยกจากผลการเรียนและระบุข้อมูลจำลองเสมอ

อัปเดต 1 ตุลาคม 2026 ใช้กับ UX prototype ใน repository นี้ คำขอและคำยืนยันล่าสุดของผู้ใช้มีน้ำหนักเหนือสเปกนี้

## 1. ทิศทางที่ต้องรักษา

Melearn เป็นพื้นที่เรียนด้วยตนเองที่ออกแบบให้ทั้งผู้เรียนและผู้สอนใช้งานได้ง่าย บุคลิกคือทันสมัย สะอาด เรียบ สุขุม และเข้าถึงได้ ผู้ใช้ยอมรับทิศทางสีและ flow ที่ปรับแล้ว พร้อมขอให้หน้าสาธารณะมีเรื่องราวและความเป็นมนุษย์มากขึ้น

ความเรียบต้องมาจากลำดับเนื้อหาที่ชัด spacing และภาพที่มีจุดประสงค์ ไม่ใช่การตัดฟังก์ชันทิ้งหรือเปลี่ยนทุกอย่างเป็นแถวการ์ดเหมือนกัน ความดูแพงไม่จำเป็นต้องใช้สีทอง พื้นครีม เงาหนัก หรือฟอนต์แฟชั่น

หน้า Landing ที่ปรับร่วมกันเป็นฐานเรื่องสี น้ำหนักภาพและบรรยากาศ อ่าน `src/pages/landing/` ประกอบ หน้า About และส่วนเรื่องราวทีมเพิ่งเพิ่มตามคำขอ ไม่ถือว่าทุกองค์ประกอบใหม่หรือทุกหน้า workspace ได้รับการยืนยันแล้ว

## 2. สีและเงา

ผู้ใช้ยืนยัน 5 ต.ค. 2026 ว่าชุดสีจากภาพตัวอย่างคือ **สีแบรนด์ Melearn**: Melearn Blue `#0066ff`, Sky Cyan `#00c2ff`, Energetic Red `#ff3b5c`, Light Background `#f7f9ff`, Deep Navy `#0b1f46` ใช้พื้นขาว/ฟ้าอ่อน น้ำเงินเป็น action หลัก แดงเป็นจุดเน้น และ navy เป็นข้อความ ห้ามย้อนกลับไปใช้เหลืองเป็นสีตกแต่ง การยืนยันนี้แทนข้อจำกัดเก่าที่ให้แดงใช้ได้เฉพาะสถานะ

| การใช้งาน | ค่าอ้างอิงปัจจุบัน | ตำแหน่งหลัก |
| --- | --- | --- |
| พื้นหลัก | `#ffffff` | หน้า public และ surface |
| Primary/action | `#0066ff` | Landing provider, `--home-blue` |
| Primary hover | `#0052cc` | `--home-blue-hover` |
| ฟ้าอ่อนสำหรับพื้นที่พักสายตา | `#f7f9ff`, `#e5f4ff` และเฉดเย็นใกล้เคียง | `--home-sky`, `--home-soft-sky` |
| จุดเน้น cyan/แดง | `#00c2ff`, `#ff3b5c` | `--home-cyan`, `--home-red` |
| ข้อความหลัก | `#0b1f46` | Landing provider, `--home-ink` |
| ข้อความรอง | `#626d82` | Landing provider, `--home-muted` |
| เส้นแบ่ง | `#e1e9f5` | `--home-line` |
| เงาพัก | `0 2px 6px rgb(0 0 0 / 3%)` | `--home-shadow-rest` |
| เงา hover การ์ดคอร์ส | `0 14px 32px rgb(0 0 0 / 10%), 0 3px 8px rgb(0 0 0 / 4%)` | `--home-shadow-raised` |

- ใช้ฟ้าเพื่อชี้ action/ลำดับ ไม่ย้อมภาพ ทุก surface และทุกเงาเป็นฟ้า
- ห้ามเพิ่ม earth tone, ivory, cream, เหลือง ม่วง หรือส้มเป็น palette ตกแต่ง สีแดงแบรนด์ใช้เน้นหัวข้อ ป้าย และภาพตกแต่งได้ สีเขียว/สีเตือนและสีสถานะอื่นยังต้องมีความหมายผ่าน semantic token
- Gradient ใช้เฉพาะที่มีเหตุผล เช่น footer ระหว่างขาวกับฟ้าอ่อน หลีกเลี่ยง gradient หลายชั้นและทุก section
- ปุ่มหลักต้องเด่น อ่านชัด และมี contrast พอ บทความ/หน้าตั้งค่าไม่จำเป็นต้องมีปุ่ม primary หลายอันแข่งกัน
- ตัวเลขในตารางเป็นฐานจาก source ไม่ใช่ข้อบังคับว่าแต่ละหน้าใช้เฉดเดียวทุกจุด ถ้าต้องปรับ theme ให้ตรวจ provider และ CSS ของหน้าที่เกี่ยวข้องร่วมกัน
- Implementation รอบ 5 ต.ค. 2026 ใช้สีแบรนด์กับ Landing `/`: Hero หัวข้อสองสี ภาพนักเรียนและกราฟิกฟ้า–แดง การ์ดข้อความลอย แถบแนะนำปิดได้ ผู้สอนเป็นสไลด์การ์ดใหญ่ บทความเลือกหมวดหมู่ได้ คอร์ส/วิธีเรียน/ทีม/รับข่าวสารใช้การ์ดมนและสีชุดเดียวกัน Footer พื้น navy ใช้โลโก้จริงและฟอนต์เดิม ไม่สร้างรีวิวหรือยอดความสำเร็จสมมติ หน้าอื่นและ `src/theme.ts` ยังใช้ธีมเดิม รอปรับตามงานเฉพาะหน้า

## 3. ฟอนต์และจังหวะการอ่าน

- ใช้ `Anuphan Variable` ที่โหลดใน `src/main.tsx` ไม่เปลี่ยนเป็นฟอนต์ใหม่โดยไม่มีเหตุผลจากผู้ใช้
- Public body ประมาณ 15–17px, editorial paragraph ใหญ่ขึ้นตามบริบท หัวข้อ public น้ำหนักประมาณ 450–550; ป้ายงานใน workspace เพิ่มน้ำหนักเมื่อช่วยแยกลำดับได้
- ภาษาไทยต้องมี line-height พอ: เนื้อหาประมาณ 1.7–1.95, หัวข้อประมาณ 1.35–1.5 ตรวจสระ/วรรณยุกต์ไม่ถูกตัด
- ใช้ขนาด/น้ำหนัก/ระยะเพื่อบอก hierarchy ไม่ทำทุกหัวข้อหนาใหญ่เท่ากัน ไม่เพิ่ม letter spacing กว้างกับภาษาไทยเพื่อให้ดูพรีเมียม
- Headline ต้องอ่านเป็นประโยค ไม่บังคับ `<br/>` จนมือถือแตกหรือไม่เป็นธรรมชาติ

## 4. Layout และ navigation

- Public ใช้ content width ที่มีอยู่ราว 1180px พร้อม gutter ตามขนาดจอ Hero/Newsletter ใช้พื้นหลังเต็มพื้นที่ได้
- จัด section ตามเรื่องราว เปลี่ยนจังหวะระหว่างภาพ เนื้อหา และเครื่องมือ มีพื้นที่ว่างที่สัมพันธ์กับเนื้อหา ไม่เพิ่ม section เพียงเพื่อให้หน้าเต็ม
- Public header มี logo จริง เมนูชัด และ action บัญชี บนจอเล็กเมื่อใช้ hamburger ให้ action สมัครสมาชิก/พื้นที่ของฉันอยู่ในเมนู ไม่ลอยโดดเดี่ยวข้าง hamburger
- Workspace header ใช้ข้อมูลบัญชีด้านขวาและเมนูบทบาทเดโมตามที่มีอยู่ Sidebar บอกหน้าปัจจุบัน
- Workspace มีปุ่มพับ sidebar บน desktop ที่มุมขวาของแถว “เมนูหลัก” ภายใน sidebar ใช้ไอคอนเล็กสีเทาและชัดขึ้นเมื่อ hover/focus เมื่อพับให้เหลือแถบไอคอนกว้าง 72px พร้อม active state, tooltip ชื่อเมนู และจุดแจ้งเตือนอินบ็อกซ์ เมนูยังกดเข้าได้ เมื่อ hover/focus โลโก้เหนือแถบไอคอนให้แสดงปุ่มขยาย กดจึงเปิด sidebar ใหญ่ มือถือใช้ hamburger และเมนูเต็ม โดยสองขนาดจอแยกสถานะกัน
- รูปบัญชีและผู้เรียนในคิวตรวจ/Analytics ใช้ `UserAvatar`: แสดงรูปจาก `user.avatar` เมื่อมี ถ้าไม่มีหรือโหลดไม่ได้ ใช้ไอคอนบุคคลพื้น neutral เป็น avatar เริ่มต้น
- กระดิ่งใน workspace แสดงแจ้งเตือนเฉพาะบัญชีปัจจุบัน มีจำนวนยังไม่อ่าน กดเพื่ออ่านและเปิดงาน/ผลตรวจ เมื่อจอแคบเมนูสลับบทบาทเดโมย้ายไปเมนูบัญชี
- อินบ็อกซ์มีเมนูในพื้นที่ผู้เรียน ผู้สอน และแอดมิน: desktop แบ่งรายการสนทนา/ข้อความ จอเล็กเปิดทีละมุมมองพร้อมปุ่มกลับรายการ ใช้ avatar และสีจากธีมกลาง
- อินบ็อกซ์ใช้พื้นที่เต็มใต้ workspace header และข้าง sidebar ไม่มีหัวเรื่องใหญ่/กรอบการ์ดชั้นนอก ชื่ออินบ็อกซ์และปุ่มข้อความใหม่อยู่ในแผงรายการสนทนา ช่องพิมพ์อยู่ท้ายหน้าจอ
- หน้าเรียนคอร์ส วิดีโอ บทอ่าน และแบบฝึกหัดมีปุ่มถามผู้สอนผ่านอินบ็อกซ์ เมื่อส่งจากบทเรียนจะแนบบริบทชื่อคอร์ส/บท/รายการเนื้อหากับข้อความแต่ละข้อ พร้อมลิงก์กลับไปยังเนื้อหา ผู้สอนเปิดบทที่เกี่ยวข้องได้
- ข้อมูลตัวอย่างอินบ็อกซ์ต้องระบุว่าเป็นข้อความตัวอย่าง มีทั้งคำถามรอตอบและประวัติตอบกลับ การเพิ่ม fixtures ไม่ลบหรือเขียนทับบทสนทนาที่ผู้ใช้ทดลองไว้
- กติกาอินบ็อกซ์ที่ผู้ใช้ยืนยัน 1 ต.ค. 2026 อยู่ใน [INBOX_PERMISSION_SPEC.md](INBOX_PERMISSION_SPEC.md): ผู้เรียนถามผู้สอนของคอร์สที่ยังมีสิทธิ์เรียน ติดต่อทีมดูแลผ่านเรื่องที่มีผู้รับมอบหมาย อ่านประวัติได้เมื่อสิทธิ์เรียนหมดแต่หยุดส่งถึงผู้สอน และแอดมินทั่วไปไม่เห็นแชตผู้เรียน–ผู้สอนทั้งหมด
- พฤติกรรมต้นแบบปัจจุบันยังเลือกแอดมินรายบัญชีและสนทนาสองบัญชี ต้องปรับเป็น flow ทีมดูแลตามเอกสารข้างต้น การมีหน้าจอนี้ยังไม่ยืนยันว่าเงื่อนไขสิทธิ์เรียนหมดหรือการมอบหมายทำงานแล้ว
- มีค้นหาบทสนทนา ตัวกรองยังไม่อ่าน บริบทคอร์ส ประวัติข้อความและสถานะอ่านแล้ว ส่งด้วย Enter/ปุ่มส่ง และขึ้นบรรทัดใหม่ด้วย Shift+Enter; ไม่แสดง auto-reply, typing หรือ online status จำลอง
- Composer อินบ็อกซ์ให้แนบ JPG/PNG/WebP และ MP4/WebM ได้สูงสุด 3 ไฟล์ต่อข้อความ ขนาดไม่เกิน 5 MB ต่อไฟล์และ 8 MB รวม แสดงตัวอย่าง ลบไฟล์ก่อนส่ง แสดงภาพพร้อม preview และวิดีโอพร้อม controls ในข้อความ จำกัดเหล่านี้ใช้เฉพาะ prototype ที่เก็บใน browser ไม่ใช่กติกา Production
- ข้อความใหม่แจ้งผ่านกระดิ่งและจำนวนบทสนทนายังไม่อ่านในเมนูอินบ็อกซ์ เปิดบทสนทนาแล้วทำเครื่องหมายอ่านเฉพาะบัญชีปัจจุบัน เก็บ draft ในแท็บเดียวโดยไม่ส่งจนผู้ใช้กดส่ง
- Public footer ใช้ `LandingFooter` ชุดเดียว เชื่อมหน้าที่มีจริง ไม่สร้าง footer อีกอันใน page ที่มี shell อยู่แล้ว
- คอร์สแยกผู้เยี่ยมชม `/courses` กับสมาชิก `/explore/courses` คนละ page/โฟลเดอร์: public แนะนำคอร์สและชวนเข้าสู่ระบบ สมาชิกใช้ workspace shell แสดงสถานะลงเรียน ความคืบหน้า และปุ่มเรียนต่อ/ลงเรียนตามบัญชีปัจจุบัน สมาชิกเปิดลิงก์ public เดิมแล้วไปหน้าสมาชิกที่ตรงกัน
- หน้ารายการสั่งซื้อ/ใบรับรองของแอดมินแยกจากหน้าบัญชีผู้เรียน แสดงชื่อและอีเมลเจ้าของรายการ มีค้นหาและตัวกรอง พร้อมลิงก์รายละเอียดที่กลับมาแล้วรักษาคำค้น หน้าจัดการผู้ใช้ค้นชื่อ อีเมล รหัสบัญชี และข้อมูลโปรไฟล์ได้ พร้อมตัวกรองบทบาทและลิงก์รายการซื้อสำเร็จของแต่ละคน
- หน้าบัญชีส่วนตัวแสดงเฉพาะรายการซื้อและใบรับรองของบัญชีปัจจุบัน แม้บัญชีเป็นแอดมิน การดูทุกคนต้องเข้าหน้า `/admin/…` และผ่าน role guard
- Responsive ต้องย้าย/ซ้อนองค์ประกอบอย่างมีลำดับ toolbar ต้อง wrap ได้ action ไม่ชน title และไม่ซ้อนกัน เมื่อ table กว้างให้จัด overflow ที่ table container
- Hover ไม่ใช่ช่องทางเข้าถึง action เพียงอย่างเดียว ผู้ใช้มือถือและคีย์บอร์ดต้องใช้ได้
- หน้า AI `/learn/ai` ใช้พื้นที่เต็ม ไม่มี navbar ด้านบน Sidebar สีอ่อนมีโลโก้จริงอย่างเดียว ปุ่มกลับไปหน้าหลักอยู่เหนือแถวแชตใหม่ ไอคอนค้นหาที่เปิดช่องค้นหา และประวัติพร้อมเมนูเปลี่ยนชื่อ/ลบ Desktop หด sidebar แล้วมีปุ่มเปิดกลับในพื้นที่แชต มือถือเปิดเป็น Drawer ช่องพิมพ์อยู่ด้านล่าง พิมพ์ `/` ที่ต้นบรรทัดเพื่อค้นหา/เลือกเฉพาะคอร์สที่ลงเรียน ใช้ลูกศรกับ Enter หรือแตะเลือกได้ Escape ปิดรายการ คอร์สที่เลือกแสดงเป็นป้ายเล็กที่นำออกได้ โดยไม่มี Select แสดงค้าง ตามคำขอ 4 ต.ค. 2026

## 5. Component และไอคอน

| พื้นที่ | ใช้ฐานปัจจุบัน |
| --- | --- |
| Workspace shell/sidebar/profile menu | Mantine + Tabler icons ใน `src/components/Shell.tsx` |
| CRUD, form, table, upload, modal, dropdown | Ant Design + `@ant-design/icons` |
| Login/register inputs, fields, buttons | shadcn/Base UI ใน `src/components/ui/` |
| Rich content | Tiptap ใน `src/components/chapter/RichTextEditor.tsx` |
| Motion/parallax | `motion/react` และ component เดิมใน Landing |

- ห้ามใช้อีโมจิแทนไอคอนหรือใช้เป็นของตกแต่ง UI ใช้ชุดไอคอนตามบริบทเดิมของหน้า ไม่ผสมหลายสไตล์ใน toolbar เดียว
- Icon-only action ต้องมีชื่อสำหรับ accessibility และ tooltip เมื่อความหมายไม่ชัด ไอคอนตกแต่งใช้ `aria-hidden`
- Input และปุ่ม auth ต้อง compact ตามของเดิม (ประมาณ 40px); form workspace ใช้ default ราว 42–44px ไม่เพิ่มความหนาทุก control จนหน้าดูอ้วน
- ใช้ Form/Field, Upload, Select, Switch, Radio, Segmented ตามชนิดข้อมูล ไม่เปลี่ยนทุกอย่างเป็น text input
- ให้หนึ่ง primary action ชัดเจนในบริบทนั้น Action รองใช้ text/outline/menu; ลบวางใน overflow เมื่อเหมาะสม แสดง danger เฉพาะการกระทำทำลายข้อมูล
- View toggle card/table ใช้ component toggle ที่มี label และสถานะ active ไม่สร้างหน้าคนละชุดจนข้อมูลต่างกัน

## 6. Asset และภาพ

- Logo: `src/assets/melearn-ui/logo.PNG`; เป็นสำเนา asset แบรนด์เดิมใน workspace ให้รักษาสัดส่วน พื้นที่หายใจ และไม่ขยายจนทับ header
- ภาพกราฟิก Melearn: `src/assets/generated/`; อ่านบันทึก asset ในโฟลเดอร์เมื่อจะเปลี่ยน ใช้ภาพที่มี neutral/white balance ไม่สร้างภาพฟ้าล้วนทุกหัวข้อ
- ภาพทีม: `public/images/founders/`; mapping ชื่อ/ตำแหน่งอยู่ใน `BrandStory.tsx` เป็นข้อมูลร่วมของ Landing และ About ห้ามเดาชื่อ ประวัติ ความเชี่ยวชาญ หรือเปลี่ยน mapping รูปเอง
- ถ้าต้องสร้างกราฟิกใหม่ ให้ทำเป็นงานเฉพาะแบรนด์ตามคำขอ ใช้ image generation เมื่อมีเครื่องมือ ไม่แทนด้วยภาพ stock จาก URL สุ่ม
- ไม่มี fake partner logos, รีวิว ยอดผู้เรียน หรือรางวัลที่ยืนยันไม่ได้ ถ้าใช้ข้อความร่าง ต้องไม่เขียนเป็นผลงานจริง
- Crop ภาพตามพื้นที่โดยรักษาจุดสำคัญ ใช้ aspect ratio และ lazy loading ตามบริบท ใส่ alt ที่อธิบายภาพเมื่อมีความหมาย

## 7. Pattern หน้า public

- Landing: ลำดับล่าสุดคือ Hero → คอร์ส → ผู้สอน → บทความ → วิธีเริ่มเรียน 3 ขั้นตอน → FAQ → ทีม → รับข่าวสาร ลบ BrandIntroduction, LearningInvitation และ LearningGuide ชุดเก่า รวมข้อความ YOUR LEARNING JOURNEY แล้ว ไม่ย้อนกลับไปใช้หน้าเก่าที่ถูกปฏิเสธ
- การ์ดคอร์ส/บทความ Landing ใช้ layout ใหม่และภาพนักเรียนแนว photographic พร้อมกราฟิกฟ้า–น้ำเงิน–แดงให้เข้ากับ Hero ภาพปกต้นแบบแบบ paper/clay ถูกแทนเฉพาะหน้า Landing ผ่าน LandingArtwork; ปกที่ผู้ใช้ใส่เองและปกในหน้าอื่นคงเดิม วิธีเรียนใช้ LearningStart โดยรักษา anchor #how-it-works
- Hero Landing: หัวข้อใหญ่ navy/น้ำเงิน/แดงอยู่ด้านซ้าย ภาพนักเรียนและกราฟิกแบรนด์อยู่ด้านขวา พร้อมการ์ดข้อความลอยและ parallax เบา ๆ ตามภาพอ้างอิง 5 ต.ค. 2026 มือถือซ้อนเนื้อหา/ภาพโดยยังอ่านและกดปุ่มได้ เคารพ reduced motion
- Newsletter: ลักษณะ hero พื้นหลังภาพเฉพาะแบรนด์พร้อม parallax และฟอร์มอีเมลตรงกลาง หลีกเลี่ยงไอคอนซองจดหมาย กล่องตกแต่งจำนวนมาก และ gradient รก
- Blog: คนทั่วไปอ่านได้ หน้ารวมมี card/table view ตามที่ผู้ใช้ขอ หน้ารายละเอียดมี hierarchy แบบเว็บอ่านบทความ ไม่ใช้ layout dashboard สำหรับอ่าน
- About: เรื่องราวของแบรนด์และสามผู้ก่อตั้ง ใช้ข้อมูลจากแหล่งกลาง ทำให้มีมนุษย์และเนื้อหาเพิ่มจากการขายคอร์ส
- Login/register: ใช้ pattern และ inputs ชุดเดียวกัน มี Google option ใน UX แต่การเชื่อมต่อบริการจริงยังเป็นงานอนาคต ไม่แสดงว่าสำเร็จถ้ายังไม่ได้เชื่อม

## 8. Pattern สร้างคอร์สและบท

- แอดมินเปิด `/admin/assignments` แล้วเลือกผู้สอนจากรายชื่อที่ค้นชื่อ/อีเมล/รหัสได้ พร้อม avatar จำนวนคอร์สและงาน จากนั้นเห็นเฉพาะงานในคอร์สของผู้สอนนั้น มีชื่อผู้สอน ปุ่มกลับ และตัวกรองคอร์ส การสร้างงานเลือกได้เฉพาะคอร์สในขอบเขตนี้ งานจัดกลุ่มตามเจ้าของคอร์สและแสดงผู้สร้างแยกกัน การแก้ไขไม่เปลี่ยนผู้สร้างเดิม

โมเดล UX: คอร์ส → บท (chapter) → รายการเนื้อหา (video / บทอ่าน / แบบฝึกหัด) บทหนึ่งมีวิดีโอหรือแบบฝึกหัดมากกว่าหนึ่งรายการได้ อย่าลดโมเดลกลับเป็นหนึ่งบทต่อหนึ่งวิดีโอ

- หน้าคอร์สบอกชื่อคอร์ส ผู้สอน ราคา สถานะ และทางเข้าจัดโครงสร้างบท ภาพปกมี upload, preview, เปลี่ยน/นำรูปออก ไม่บังคับกรอก URL อย่างเดียว
- Curriculum เป็นมุมมองโครงสร้าง: สแกนชื่อบทและเนื้อหา จัดลำดับ เพิ่มบท และเปิด workspace ของบทได้ ลดการซ้ำของปุ่มแก้/ลบทุกแถว
- Chapter workspace เป็นพื้นที่ทำงาน: บอกคอร์ส/บทที่กำลังแก้ แสดงรายการเนื้อหา เลือกรายการเพื่อแก้ มีเพิ่มเนื้อหา ดูตัวอย่าง และสถานะบันทึก
- แยก metadata ของบทออกจากการแก้เนื้อหา การเปิดหน้าแก้บทต้องมีมากกว่าชื่อกับคำอธิบายเมื่อผู้ใช้กำลังจัดเนื้อหา
- วิดีโอ: เลือกแหล่ง/อัปโหลดตามที่ prototype รองรับ แสดง preview และ validation; ไม่ปล่อยช่อง URL ที่ไม่มีคำอธิบายให้ผู้ใช้เดาเอง
- บทอ่าน: rich editor พร้อม paragraph, headings, lists, links และภาพ ไม่ใช้ textarea ยาวเป็น editor หลักในงานใหม่
- แบบฝึกหัด: เพิ่มเป็นข้อ เลือกประเภทคำถาม กำหนดโจทย์ ตัวเลือก/เฉลย คะแนน และเกณฑ์ผ่าน ข้อเขียน/ภาพมีขั้นส่งคำตอบและผู้สอนตรวจให้คะแนน
- หน้าตรวจงานใช้ workspace กว้าง แยกคำตอบ/ภาพงานจากแผงคะแนนประมาณ 360–400px บน desktop รูปขยายและซูมได้ จอเล็กซ้อนแผงคะแนนใต้คำตอบ ยังคงให้คะแนนรวมข้อเขียนตาม flow เดิม
- คิวตรวจใช้ป้ายประเภทคำตอบและอายุงานสี neutral ไม่ตีอายุงานเป็นระดับเร่งด่วนเอง ปุ่มตรวจงานรายแถวใช้ outline และรักษา course/mode/คำค้นเมื่อกลับจากการตรวจ
- คะแนนและความคิดเห็นที่กำลังกรอกเก็บเป็นฉบับร่างในแท็บเดียวเมื่อสลับงาน โดยยังไม่เป็นผลตรวจจนกดบันทึก มีข้อความระบุสถานะและแจ้งเมื่อเก็บฉบับร่างไม่ได้
- Prototype มีแจ้งเตือนในระบบเมื่อผู้เรียนส่งข้อเขียน/ภาพถึงผู้สอน เมื่อผู้สอนบันทึกผลถึงผู้เรียน และเมื่อสร้าง/แก้งานมอบหมายถึงผู้เรียนเป้าหมาย เป็นข้อมูลในเบราว์เซอร์เดียวกัน ยังไม่ใช่ email/push หรือการแจ้งเตือนข้ามอุปกรณ์ Production
- แสดง feedback ใกล้จุดที่แก้และบอกว่ายังไม่บันทึก เมื่อออกจากงานที่แก้ค้างต้องรักษาข้อมูลหรือให้เลือกบันทึก/ทิ้ง/อยู่ต่อ
- ลบต้องบอกว่าจะลบรายการใดและผลกระทบ เมื่อทำได้ใช้ confirmation หรือ undo ตาม pattern เดิม

## 9. บทบาทและพฤติกรรมที่ใช้ทบทวน prototype

| ผู้ใช้ | ขอบเขตที่ออกแบบไว้ |
| --- | --- |
| ผู้เยี่ยมชม | Landing, About, รายการ/รายละเอียดคอร์ส, blog, login/register |
| ผู้เรียน | คอร์สที่มีสิทธิ์เรียน วิดีโอ/บทอ่าน แบบฝึกหัด/ส่งภาพ รายการซื้อ และใบรับรอง |
| ผู้สอน | คอร์สของตน บท/เนื้อหา/แบบฝึกหัด ผู้เรียน และตรวจคำตอบในขอบเขตคอร์ส |
| แอดมิน | สร้าง/แก้คอร์สรวมถึงคอร์สของผู้อื่น จัดการผู้ใช้/ผู้สอน/บทความ/รายการซื้อ/ใบรับรอง |

- ผู้สอนเข้าผ่านการเชิญหรืออนุมัติของแอดมินตาม flow ที่ตกลง ไม่เปิดสมัครเป็นผู้สอนที่ได้รับสิทธิ์ทันทีเอง
- ตอนนี้ blog ให้แอดมินเขียน/จัดการได้เท่านั้น บทอ่านในบทเรียนเป็นคนละชนิดกับ public blog
- ซื้อแยกรายคอร์สและมีคอร์สฟรี Payment เป็น simulation; ใบรับรองมี flow เรียนครบและผ่านแบบฝึกหัด รวมข้อเขียนที่ตรวจแล้ว
- ตารางนี้เป็นทิศทาง UX ตรวจ source ปัจจุบันก่อนสรุปว่าแต่ละพฤติกรรมทำได้ครบแล้ว การซ่อนเมนู/ตรวจ role ฝั่ง client ไม่ใช่ permission enforcement สำหรับ Production
- MCP, CLI และ Melearn skill เป็นเรื่องที่เคยคุยสำหรับอนาคต ไม่อ้างว่ามี server/tool ใช้งานจริงแล้ว และไม่เพิ่มสิทธิ์ผ่าน AI โดยข้ามบทบาท

## 10. Motion การเข้าถึง และการส่งงาน

- ใช้ Motion ที่มีอยู่สำหรับ fade/reveal และ parallax อย่างพอดี ไม่เพิ่ม effect ที่แย่งความสนใจจากการอ่านหรือบังคับรอ animation
- เคารพ `prefers-reduced-motion` / `useReducedMotion`; เมื่อปิด motion ต้องเห็นเนื้อหาครบและใช้งานได้
- ทุก field มี label, error อ่านรู้เรื่อง, focus มองเห็น เมนู/dialog ใช้คีย์บอร์ดได้ ข้อมูลสำคัญไม่สื่อด้วยสีเพียงอย่างเดียว
- สถานะ empty/loading/error/saved ให้มีตามเส้นทางที่แก้ ไม่ใส่ปุ่มไม่มีผลหรือ fake success
- ตรวจหน้าที่เปลี่ยนและ flow หลักอย่างพอประมาณ เขียน responsive ด้วย การตรวจทุกหน้า/ทุกอุปกรณ์ไม่ใช่ขั้นอัตโนมัติของงานย่อย
- Build ผ่านคือ code bundle ได้ ผู้ใช้ตรวจแล้วจึงเป็น visual approval
