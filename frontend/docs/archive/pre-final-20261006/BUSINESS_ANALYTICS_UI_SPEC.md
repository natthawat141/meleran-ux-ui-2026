# ภาพรวมธุรกิจและรายงานการเงิน — UX/UI specification

สถานะ: prototype ที่ผู้ใช้สั่งให้เตรียม UX/UI และสเปก วันที่ 1 ต.ค. 2026 ไม่ใช่การอนุมัติ backend, payment provider หรือกติกาบัญชี Production

## วัตถุประสงค์และผู้ใช้

ให้เจ้าของกิจการ/ผู้ดูแลมองเห็นการเข้าชม การเข้าเรียน การลงทะเบียน การซื้อ และรายการเงินที่ประกอบเป็นยอด โดยยังแยกจากหน้าวิเคราะห์ผลการเรียนและงานปฏิบัติการเดิม

Prototype แสดงเฉพาะ role admin ผ่าน route guard เดิม ส่วน permission รายละเอียดและ organization scope สำหรับระบบจริงเป็นข้อเสนอใน [สเปกข้อมูล](BUSINESS_ANALYTICS_DATA_SPEC.md) ต้องให้เจ้าของระบบยืนยันก่อนใช้จริง

## หน้าที่เตรียมไว้

| Route | หน้าที่ |
| --- | --- |
| `/admin` | ภาพรวมงานระบบเดิม เพิ่มผู้เรียน ผู้สอน การลงทะเบียน และคำสั่งซื้อที่รอ พร้อมทางเข้ารายงาน |
| `/admin/business-analytics` | ผู้เข้าชม/ผู้เรียนไม่ซ้ำ แนวโน้มรายวัน ช่วงเวลาเข้าเรียน funnel และผลรายคอร์ส |
| `/admin/reports/finance` | เงินชำระสำเร็จ เงินคืน ค่าธรรมเนียม ยอดหลังหัก กราฟ และรายการประกอบยอด |
| `/admin/analytics` | ผลการเรียน/ความคืบหน้า/งานรอตรวจของต้นแบบปัจจุบัน ไม่ถูกแทนด้วยยอดธุรกิจ |

## การจัดข้อมูลและหน้าตา

- รักษา white/light sky blue, primary #0074e8, Anuphan และ Shell เดิม ใช้ Ant Design สำหรับตัวกรอง ตาราง ปุ่ม และ Drawer
- ไม่ใช้สีรุ้งเพื่อแยกตัวชี้วัด กราฟใช้ฟ้าและ neutral; heatmap ใช้ระดับความเข้มของฟ้าเพียงชุดเดียว
- ด้านบนมีชื่อหน้า ข้อมูลจำลอง และตัวกรอง ตามด้วย KPI แบบแถว ไม่ทำทุกตัวเลขเป็นการ์ดกระจาย
- กราฟหนึ่งชุดใช้หน่วยเดียว เลือกตัวชี้วัดจาก Select มีวันที่ หน่วย ข้อความเมื่อ focus/hover และตารางอ่านตัวเลขได้
- จอเล็กตัวกรองเรียงลง กราฟย่อตามพื้นที่ ตาราง/heatmap เลื่อนภายใน ไม่ทำทั้งหน้าล้นแนวนอน

## ตัวกรองร่วม

เลือก 1/7/30/90 วันถึงวันอ้างอิงตัวอย่าง หรือระบุ start/end เอง พร้อมทุกคอร์ส/รายคอร์ส

URL เก็บ `start`, `end`, `course`, `metric`, `heatmap` เพื่อรักษาสถานะเมื่อ refresh/back เปิดลิงก์ได้ วันที่เป็น ค.ศ. ISO แต่เวลารายการแสดงไทย Asia/Bangkok

ตัวอย่างมี coverage 2026-07-01 ถึง 2026-10-01 วันอ้างอิงนี้ไม่ใช่ “วันนี้” ของระบบจริง ไม่เปลี่ยนตามนาฬิกาเครื่อง วันที่นอก coverage ต้องเป็นไม่มีข้อมูล ไม่ลากกราฟเป็นศูนย์ ไม่คำนวณเปอร์เซ็นต์เติบโตจากฐานที่ไม่มีข้อมูล

ช่วงกลับด้าน วันที่ผิด คอร์สที่ไม่มี และช่วงเกิน 366 วันแสดงข้อความแก้ไข โดยไม่คำนวณรายงาน ไม่ส่งออกข้อมูลผิดช่วง

## ภาพรวมธุรกิจ

1. ผู้เรียนเข้าเรียน: unique actor ที่มี learning_engaged ในช่วง ไม่ใช่รวม DAU
2. ผู้เข้าชมคอร์ส: unique actor ที่มี course_viewed แยกจากผู้เรียนที่ลงทะเบียน
3. ลงทะเบียนใหม่: รายการ enrollment_created รวมฟรีและซื้อสำเร็จ
4. ยอดชำระ: confirmed payment ก่อนคืนเงินและค่าธรรมเนียม
5. แนวโน้มรายวัน: สลับ active learners, visitors, sessions, enrollments, purchases; DAU ดูจากวันนั้นในกราฟ/ตาราง
6. Heatmap วันในสัปดาห์ × ชั่วโมง: สลับ unique learners ต่อช่อง หรือจำนวนธุรกรรมซื้อสำเร็จ ผู้เรียนอาจอยู่หลายช่อง ไม่บวกทุกช่องเป็นคนไม่ซ้ำ
7. Funnel: ดูคอร์ส → เริ่ม checkout → ซื้อสำเร็จ ใน session/course เดียวกันตามเวลาและภายในช่วงที่เลือก คอร์สฟรีไม่ต้องผ่าน payment funnel
8. ตารางคอร์ส: visitors, active, enrollments, purchases, collected; คลิกชื่อเพื่อกรองคอร์สในหน้า
9. CSV รายวัน: ใช้ช่วง/คอร์สเดียวกับหน้า มี timezone, classification และ coverage ไม่ใช่ส่งออกข้อมูลส่วนตัว

## รายงานการเงินขั้นต่ำ

- แสดง 4 ยอด: ชำระสำเร็จ, คืนเงินสำเร็จ, ค่าธรรมเนียม, ยอดหลังหัก
- สูตรยอดหลังหัก = เงินชำระ − เงินคืน − ค่าธรรมเนียม เป็น operational transaction report ไม่ใช่กำไร รายได้ที่รับรู้ทางบัญชี หรือเงินโอนเข้าธนาคาร
- เงินคืนเลือกตามวันที่คืนสำเร็จ แม้ payment อยู่ก่อนช่วง ต้องมีคำอธิบายรายการคืนข้ามช่วง
- ตารางประกอบยอดเป็น signed ledger: payment บวก, refund/fee ลบ รวมเท่ากับยอดหลังหักเมื่อไม่กรองเฉพาะตาราง
- ค้นหาและประเภทเป็นตัวกรองตาราง/CSV เท่านั้น มีข้อความบอกขอบเขต ยอดสรุปยังใช้ช่วงวันที่/คอร์ส
- Drawer เปิดเลขธุรกรรม คำสั่งซื้อ คอร์ส วันที่ จำนวนเงิน และ payment ต้นทาง ข้อมูล demo ไม่ลิงก์ไปหา order จริงที่ไม่มี
- CSV มี transaction IDs, UTC timestamps, THB และ integer satang พร้อม UTF-8 BOM และการป้องกันสูตรจากข้อความใน spreadsheet
- ไม่สร้างใบเสร็จภาษี ยอด settlement หรือปุ่มคืนเงินจริงใน prototype นี้

## ขอบเขตข้อมูลและสถานะ

Fixtures `src/mocks/businessAnalytics.ts` สร้างข้อมูลสมมติแบบ deterministic จาก course catalog ปัจจุบัน ไม่เติม orders/users เข้า store ไม่ reset browser data ไม่มีการติดตามผู้ใช้จริง

หากแก้ราคาหรือสถานะคอร์สในต้นแบบ fixtures จะถูกสร้างใหม่เพื่อทดสอบ UI ระบบจริงต้องใช้ราคา/ชื่อ snapshot ของธุรกรรมและประวัติ ไม่สร้างประวัติย้อนหลังจากราคาปัจจุบัน

Source ปัจจุบันมีเพียง synthetic synchronous data; production loading, API error/retry, denied export, stale data, empty state, pagination และ partial coverage เป็น acceptance ของ integration ยังไม่ได้จำลอง network ทุกสถานะในหน้านี้

## Acceptance เมื่อเชื่อม API จริง

- คำนวณตรงกันระหว่าง KPI กราฟ รายคอร์ส ledger และ export ภายใต้ scope เดียวกัน
- ป้องกันผู้ไม่มี permission ที่ server ทั้งอ่าน/export/direct URL ไม่อาศัยการซ่อนเมนู
- ระบุ data freshness, coverage และ effective timezone/currency; ห้ามเทียบช่วงที่ไม่ครบโดยไม่มีข้อความ
- Loading ไม่แสดงศูนย์แทนรอข้อมูล; error มี retry; empty แยกจาก no coverage
- เลขเงินจริงไม่มี floating point rounding drift, ไม่บวกคนไม่ซ้ำข้ามวัน/คอร์ส, duplicate webhook ไม่เพิ่มยอด
- เปิด Drawer/CSV จาก scope ที่ได้รับอนุญาต ไม่มี PII ที่ไม่จำเป็น
- ไม่มีการส่งข้อความ/ชำระ/คืนเงินโดยการเปิดรายงาน
